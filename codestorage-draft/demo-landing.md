    <section class="cs-section">
      <h2>Surfaces</h2>
      <p>
        A theme earns confidence by working beyond a single hero. This demo keeps the same
        content set for every candidate so visual differences come from CSS rather than copy.
      </p>
      <ul>
        <li><a href="/">Home</a> tests navigation, sidebar, hierarchy, and calls to action</li>
        <li><a href="/kitchen-sink">Kitchen sink</a> tests Markdown, code, tables, media, and callouts</li>
        <li><a href="/blog">Blog list</a> tests repeated summaries, metadata, and scanning rhythm</li>
        <li><a href="/blog/first-post">Blog post</a> tests a focused long-form reading surface</li>
      </ul>
    </section>
    <section class="cs-section">
      <h2>Review matrix</h2>
      <p>
        The current preview has been reviewed in both supported color modes and at representative
        desktop and mobile viewports. Search stays outside that result until the demo receives the
        required Flowershow feature entitlement.
      </p>
      <ul>
        <li>Desktop viewport: 1280 × 900</li>
        <li>Mobile viewport: 390 × 844</li>
        <li>Color modes: light and dark</li>
        <li>Status: Preview — review evidence is not release authorization</li>
      </ul>
    </section>
    <section class="cs-section">
      <h2>Theme ingredients</h2>
      <p>
        The visual system is ordinary, inspectable CSS. Flowershow tokens set the palette and
        typography; semantic classes style navigation, content, sidebars, code, and blog surfaces.
      </p>
      <ul>
        <li>Open IBM Plex Mono substitution instead of a commercial reference font</li>
        <li>Light and dark token sets selected by the page theme attribute</li>
        <li>Semantic Flowershow class hooks rather than copied application markup</li>
        <li>Landing-only rules scoped under <code>.cs-landing</code></li>
      </ul>
    </section>
    <section class="cs-section">
      <h2>Configuration</h2>
